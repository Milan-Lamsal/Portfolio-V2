CASE STUDY 02 / FRONTEND / INFORMATION DESIGN

News Explorer.

Different sources. One reading flow. A news reader with saved articles and thoughtful browser caching.

01

The problem

News providers expose different response formats. A reader still needs a consistent way to browse stories, revisit articles, and move between categories.

02

The objective

Build a React reading experience that normalizes provider data and remembers useful state in the browser.

03

The approach

Guardian stories and MediaStack health news map into a shared article shape. Category pages, date filters, a loaded-article text filter, and saved stories keep navigation focused.

04

Technical implementation

React Router handles views. Axios retrieves data. IntersectionObserver loads pages of ten articles. Bookmarks use localStorage; LocalForage caches API results with category-specific expiry windows.

05

Challenges & tradeoffs

Caching reduces repeated fetches but introduces staleness. The source uses 15-minute headline, 30-minute category, and 60-minute health caches, plus a manual clear-cache control. Text search covers already loaded articles, not the provider’s entire archive.

06

The result

The repository contains a working frontend implementation with multiple news views, infinite scrolling, saved articles, and a theme toggle. Authentication and personalized feeds are roadmap ideas, not delivered features. Live deployment availability has not been verified.

07

Engineering takeaway

Normalizing data at the service boundary keeps UI components independent of individual provider response shapes. A cache also needs explicit expiry and a way to recover from stale data.
